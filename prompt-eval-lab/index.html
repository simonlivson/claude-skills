Prompt Eval Lab: A vs B

Run two versions of a prompt on the same test cases, have Claude grade every answer against your rubric, and see which version wins. The example below is a CV summary tailored to job posts. Replace it with your own.

1The input you know

Why: an eval works best when you can check the truth yourself. You know exactly what is and isn't in your own CV, so you can spot an invented skill at a glance.

Example. Paste your own summary

2Test cases

Why: one good answer proves nothing. Mix easy matches, a stretch role, a neighboring field and one trap that asks for skills you don't have. The trap is where weak prompts start inventing experience.

3Rubric

Why: “looks good” isn't a score. Each line is a pass/fail check. Claude judges the text criteria; the word limit is counted by code, because a rule a program can check shouldn't depend on a model's opinion.

4Two prompt versions

Why: change one thing at a time when you can. Here A is a plain request and B adds a role, explicit rules and an output format.

Use {cv} and {job} where the CV summary and each job post should go. Use {maxWords} for the rubric's word limit, so a prompt never asks for a different limit than the one it's graded on.

5Run and score

How it grades: for each test case, Claude writes an answer with A and with B, then a stronger Claude model grades both against the rubric. The grader sees them as X and Y in random order, so it can't favor one version by its position.

Run twice or more so one lucky answer can't decide the winner.

Runs on your Claude account. Takes about a minute per test case.
